## Принципы (не нарушать)

1. Бот НИКОГДА не спрашивает парольную фразу (сид-фразу), приватный ключ, пароли.
2. Если пользователь прислал похожее на парольную фразу — предупредить, не сохранять.
3. .env и база данных (botdata/*.db) никогда не коммитятся в Git.
4. Награда — одна на пользователя (UNIQUE(tg_id, code) в таблице rewards).
5. Реальные выплаты — сначала только вручную, с проверкой админом.
6. Контент — без обещаний дохода, строго обучающий тон.
7. Бейджи и статусы разделены: бейджи — это история достижений, статус — текущий наивысший уровень.

# PRIZM Bots — прогресс проекта

## Состав проекта

Monorepo `prizm_quest_bot` на GitHub (svetlana-myhub/prizm_quest_bot).
Два самостоятельных бота в одном репозитории:

1. **Квест-бот** (`bot.py`) — обучающий квест сообщества Prizm
2. **Алерт-бот** (`alert_bot.py`, @swap_pzm_bot) — оповещения о сделках PZM на DeDust

Правила сосуществования: боты НЕ импортируют друг друга; общее выносится
в общие модули (db.py, config.py, будущие wallets.py/ton_utils.py);
каждый со своим токеном и точкой входа; в WSGI — каждый в своём потоке с try/except.

Рабочие машины: Mac, Windows, сервер PythonAnywhere — синхронизация через git
(правка → commit → push → pull на остальных → Reload на сервере).

## Уроки проекта (грабли, на которые не наступаем повторно)

1. 1 токен = 1 экземпляр: параллельный запуск → 409 Conflict
2. В группах бот должен быть админом (privacy mode), иначе не видит
   обычные сообщения и выбор темы не работает
3. В официальном Telegram API нет getForumTopic — название темы читаем
   из служебного сообщения forum_topic_created в истории чата
4. print() в uWSGI буферизуется и не виден — используем logging (stderr)
5. WSGI-файл вне git: после правок кода не забыть ручную правку WSGI + Reload
6. PythonAnywhere гоняет внешние запросы через свой прокси: 503 прокси —
   авария PA, watchdog её переживает, ложные DEGRADED гасим порогом 15 мин
7. В каналах команды не работают — управление через /chats из лички
8. «Already up to date» на сервере = правка не доехала до GitHub:
   проверять git status / commit / push на рабочей машине
9. Долгая перезагрузка PA («took a long time to reload») — обычно норма:
   проверяем руками сайт и /health
