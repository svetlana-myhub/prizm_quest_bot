# PRIZM Bots — прогресс проекта

Обновлено: 20 сентября 2026

## Суть проекта

Два самостоятельных Telegram-бота сообщества Prizm в одном репозитории:

1. **Квест-бот** (`bot.py`, @PrizmQuestBot) — обучающий квест: просто и с
   жизненными примерами объяснить основы, научить безопасности (парольная
   фраза!), провести квест и выдать награду по правилам.
2. **Алерт-бот** (`alert_bot.py`, @swap_pzm_bot) — оповещения о сделках PZM
   на DeDust, курс, статистика и история торгов.

- Репозиторий: https://github.com/svetlana-myhub/prizm_quest_bot (приватный)

## Принципы (не нарушать)

1. Бот НИКОГДА не спрашивает парольную фразу (сид-фразу), приватный ключ, пароли.
2. Если пользователь прислал похожее на парольную фразу — предупредить, не сохранять.
3. .env и база данных (botdata/*.db) никогда не коммитятся в Git.
4. Награда — одна на пользователя (UNIQUE(tg_id, code) в таблице rewards).
5. Реальные выплаты — сначала только вручную, с проверкой админом.
6. Контент — без обещаний дохода, строго обучающий тон.
7. Бейджи и статусы разделены: бейджи — история достижений, статус — текущий уровень.
8. Боты НЕ импортируют друг друга; общее выносится в общие модули
   (db.py, config.py, market.py; будущие wallets.py/ton_utils.py);
   у каждого свой токен и точка входа; в WSGI — свой поток с try/except.

  сообщения forum_topic_created; фолбэк — ручное имя или главная тема)

### Настройки чата (/alert в чате или /chats из лички)
- вкл/выкл оповещения
- фильтр: все / покупки / продажи
- мин. объём: 0 / 1 000 / 10 000 / 50 000 PZM
- категория холдеров: 1–49 / 50+ / 100+
- куда: главная тема / выбранная тема (кнопка с названием)
- картинка: сменить / сбросить
- 🧹 Автоочистка: вкл/выкл — в чате остаётся только последнее оповещение
  (перед новым удаляется предыдущее; действует на сделки и тесты;
  «👀 Предпросмотр» в цепочку не входит); нужно право «Удалять сообщения»
- 👀 Предпросмотр — превью на месте настройки (не мусорит в канал)
- 📣 Тест оповещения в чате — тест в целевой чат (участвует в автоочистке)
- 🔕 Отключить

### Статистика и история (добавлено 19–20.09.2026)
- Журнал сделок: таблица `trades` (ts, is_buy, pzm_amount, other_sym,
  other_amount, usd_value, event_id UNIQUE) — пишется монитором в реальном
  времени; история с сентября 2025 загружена скриптом `fill_history.py`

  часовые снапшоты пишет поток `rate_snapshotter`; годовая история

- `/stats`: периоды сегодня / 7д / 30д / 6 мес / 1 год / всё время;
  фильтры все / 🟢 покупки / 🔴 продажи; сделки, объём PZM и $, крупнейшая,
  средняя, полоска 🟩/🟥
- `/rate`: три валюты (USDT, GRAM, RUB), изменения 24ч (tonapi) и
  7д/1мес/1год (снапшоты, «резиновый» допуск sec//12), ликвидность пула;
  фолбэк-строка «с начала торгов (N дн)»
- `repair_trades.py` — пересчёт usd_value сделок по снапшотам задним числом
- Общий рыночный модуль `market.py` (курсы, RUB, ликвидность, периоды) —
  для обоих ботов

## Уроки проекта (грабли, на которые не наступаем повторно)

1. 1 токен = 1 экземпляр: параллельный запуск → 409 Conflict
2. В группах бот должен быть админом (privacy mode), иначе не видит
   обычные сообщения и выбор темы не работает
3. В официальном Telegram API нет getForumTopic — название темы читаем
   из служебного сообщения forum_topic_created в истории чата
4. print() в uWSGI буферизуется и не виден — используем logging (stderr)
5. WSGI-файл вне git: после правок кода не забыть ручную правку WSGI + Reload
6. PythonAnywhere гоняет внешние запросы через свой прокси: 503 прокси —
   авария PA, watchdog её переживает, ложные DEGRADED гасим порогом 15 мин
7. В каналах команды не работают — управление через /chats из лички
8. «Already up to date» на сервере = правка не доехала до GitHub:
   проверять git status / commit / push на рабочей машине
9. Долгая перезагрузка PA («took a long time to reload») — обычно норма:
   проверяем руками сайт и /health
10. Бесплатный PA: весь внешний трафик идёт через прокси и только на белый
    список сайтов; без прокси интернета нет вовсе. Новые API (DYOR) с сервера
    недоступны (403/Network unreachable) — разовые загрузки данных делаем
    с локальной машины и переносим результат файлом (snaps.csv → импорт)
11. Исторические тики цены приходят только в моменты изменения цены (паузы
    до суток+): допуск поиска ближайшей точки растёт с периодом (sec // 12),
    иначе дальние периоды показывают «—» при полной истории
12. Заменяя функцию целиком, сверяй старое и новое содержимое построчно:
    так однажды потерялся блок set_my_commands (меню команд)
13. git add с неверным путём → «pathspec did not match»: смотри подсказку
    git ниже (modified: docs/...) — там настоящий путь к файлу
